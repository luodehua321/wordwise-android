# 安卓内存与启动检查（2.0.10）

测试日期：2026-10-26。设备为本机专用 arm64-v8a 模拟器，Android API 37；没有连接安卓真机。以下是模拟器实测，不能直接当成某台手机的性能承诺。

## 实测结果

每组重复三次，每次先结束应用进程，再启动应用，保留数据库与学习记录。等待完全可操作后再等待三秒采集 PSS。表内为中位数；首帧与完整可用时间分别记录，不把加载页当成加载完成。

| 指标 | 扩充词库后的调试基准包 | 仅音标读取优化的调试包 | 前阶段优化正式包 | 最新扩充词库正式包 |
| --- | ---: | ---: | ---: | ---: |
| 首帧 TTID | 1.336 秒 | 1.383 秒 | 0.896 秒 | 1.189 秒 |
| 完整可操作 TTFD | 10.145 秒 | 9.966 秒 | 2.471 秒 | 3.148 秒 |
| 总 PSS | 145.4 MiB | 135.1 MiB | 63.2 MiB | 72.6 MiB |
| Java Heap PSS | 49.8 MiB | 39.8 MiB | 32.5 MiB | 41.8 MiB |

前阶段正式包三次完整可用时间为 2.471、2.629、2.062 秒；PSS 为 63.2、68.5、61.4 MiB。调试包到正式包的差异包含非调试运行、R8 代码优化和音标解析调整，不能把全部收益归因于音标改动。它也不是与上次 v2.0.9 在相同词库上的单因素比较。

最新扩充词库包在模拟器重新启动后测量，三次完整可用时间为 3.692、3.066、3.148 秒，PSS 为 74.1、72.2、72.6 MiB。词库比前阶段又增加了2,689个原缺例句词，运行时缓存环境也不同；不能把前后差异完全归因于新增内容。最新包 SHA256 为 e05fd3fb00c487aaf7ea53efd0f893e65cdb595746fb34809b057f9661a9c8c4。

最新词库升级后的首次打开为 **14.140 秒**，包含词库刷新。

前阶段词库合并后的首次打开为 11.700 秒，包含整库刷新；之后的三次日常冷启动不再导入。此前调试基准包升级首次打开为 34.279 秒，两者构建方式和运行时不同。临时数据库的升级保护测试耗时 3.010 秒，它只测仓库准备，不包含应用界面，不能与完整启动时间混用。

原始逐次日志、PSS 明细与汇总位于 `dist/validation-v2.0.10/performance/`。并行编译期间采集的一组数据另行保留，但未用于上表，避免把构建竞争混入结论。没有执行系统页缓存清空，各组三次测量之间也不重启模拟器；最新扩充词库测量是在专用模拟器重新启动后进行。这里的“冷启动”指应用进程已结束。

## 已实现的优化

1. **交付正式构建。** 之前主要交付 debug APK；现在交付启用 R8 和资源压缩的 release APK，最新包约 30.22 MiB。沿用既有安装证书、应用 ID 和数据库，因此可覆盖升级。调试构建仍保留用于开发与回归测试。
2. **音标流式读取与去重。** `RelatedPronunciationCodec` 不再把整个 JSON 解析成对象树。主词库已具备相应口音的词跳过，空补充项也不驻留。在相同资产、相同词索引的五轮交替测试中，保留表项由 24,826 降到 2,880；保留堆增量中位数由 4,030,464 B 降到 397,312 B，约减少 90%。热代码解析耗时中位数由 71.7 ms 降到 51.1 ms。这是解析器局部测试，不能当作整个应用的启动时间。全部词的实际美式、英式回退结果逐项对照一致。
3. **升级直接使用预编译词库。** 词库版本变化时，从经过 SHA256 和来源版本检查的预编译数据库分批读取词条，避免重新对全库 JSON 解码、验证字段、再编码。使用 Room `@Upsert` 更新单词，不删除或替换学习数据库，不采用会触发外键级联删除的 `INSERT OR REPLACE`。临时文件完成后关闭并删除；缓存不可用时保留原 JSON 路径。
4. **记录真实可用时间。** 用 `ReportDrawnWhen` 等待单词准备完成；分阶段记录仓库、音标和单词就绪耗时，避免仅看首帧误判启动速度。日志只有耗时，不包含昵称、词汇作答记录等个人内容。

## 下一步值得做的优化

- **详情按需加载，优先降低常驻内存。** 当前仍一次性加载 28,167 个词及全部例句、关系和来源字符串。出词只需要 ID、难度等基础字段。可把基础索引常驻，当前单词和详情页从 SQLite 按 ID 取完整内容，再用有容量上限的缓存保留最近详情。需要同时验证校准抽样、详情页和返回行为；尚未实现，不承诺具体节省值。
- **学习日志改为 SQL 聚合与范围读取。** `readSnapshot()` 读取全部历史日志，`MainViewModel.refresh()` 再按日期分组。记录多年后成本会增长。可针对今日/本周统计、错词、近期调度分别查询，保留完整历史用于必要的恢复操作，并对跨日与时区变更做回归测试。
- **生成应用自己的 Baseline Profile / Startup Profile。** 覆盖启动、词库二进制读取、出词、翻页和详情展开；使用正式构建在真机上测量，减少首次执行解释/JIT开销。目前已打包依赖库带来的 profile，尚未生成本应用完整用户路径的专用 profile。
- **构建期生成更小的音标补充资产。** 当前运行时仍需要扫描全表，虽然只保留必要项。可在构建阶段生成按词库哈希绑定的最小补充表，进一步减少扫描与解压；保留原始来源表和失效回退路径。

没有以三次短测宣称“完全没有内存泄漏”。本次解决的是可复现的启动、常驻对象与升级解析开销；真机长时间连续学习和大量历史记录场景仍应单独测量。

## 复现

使用项目专用模拟器：

```sh
python3 tools/measure_android_runtime.py --serial emulator-5582 --phase local-check --runs 3
```

脚本只接受模拟器，不清除学习数据。仓库测试、音标解析对照和升级保护测试均位于 `app/src/androidTest/java/com/yuxuan/lingo/data/`，只创建并删除自己的临时测试数据库。
